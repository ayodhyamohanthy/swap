### The finding that changes the size of the job

`schema.sql` has **no role DDL, no schema DDL and no extension DDL** — it assumes
Supabase already provisioned the `auth` schema and the roles `anon` /
`authenticated` / `service_role`, and it uses exactly two functions from that
schema. So **all 43 RLS policies port byte-identically** behind a small
`app/azure/sql/00-compat.sql` that supplies `auth.uid()`, `auth.role()` and the
three roles. The alternative in `docs/17` §W1-alt — "RLS-as-auth becomes
Worker-enforced authorization" — means re-deriving 43 policies of security logic
in TypeScript, which is strictly larger and strictly riskier.

The implementation detail that makes it work: **`set_config(name, value, true)`,
not `SET LOCAL x = $1`** — the latter does not accept a bind parameter in the
extended query protocol. Identity and query must share one explicit transaction;
that is the load-bearing assumption, and a pooler handing over a connection still
carrying a previous request's `service_role` is the fail-open case (needs
`RESET ALL` on checkout).

Also corrected: `docs/17` §W1-alt lists "Storage → R2" and "Realtime → 10s
polling" as rebuild work, but **neither is used anywhere in `app/src`**. And the
shim must live outside `schema.sql`/parts/migration, or it breaks the
byte-consistency invariant `tests/schema.test.ts` enforces — and would make the
schema un-installable on Supabase, which is the reverse migration §0 requires.

### `npx tsc --noEmit` from the repo root is not a typecheck

It prints tsc's **help text** and exits **0**. `tsconfig.json` lives in `app/`,
and tsc with no tsconfig and no input files prints usage instead of failing, so
the gate reads as passed while nothing was compiled. The real gate is
`npm run typecheck`, which runs `tsc --noEmit` inside the workspace. I caught it
because the output was help text rather than silence — but the exit code said 0,
and an exit code is what a script checks. Same family as every other trap in
this file: **a command that names one thing and measures another.**

Also, the shell here is zsh: `$PIPESTATUS` is empty, it is `$pipestatus`. My
`echo "---EXIT: ${PIPESTATUS[0]}---"` printed nothing and looked like a pass.

### The file was tracked, committed, and inert

Item 3's handoff had been committed to `workflows/seatswap-backup.yml` at the

had never run, and the board said only "commit the file". The file's own first

**The generalisable part:** `git status` and `git log` both showed a healthy

the path and fails if a second copy reappears under `workflows/`, while the
test suite covers the contents. A string-level guard cannot see a directory.
