### What the parallel commit got right that I did not

`882ebcf` (L9, "Buffy") shipped `app/src/lib/telemetry.ts`: `VITE_POSTHOG_KEY` /
`VITE_POSTHOG_HOST` / `VITE_SENTRY_DSN`, client-side, a `scrubMeta` PII filter,
one `/capture/` per event with `keepalive`, Sentry config-only. Its argument is
correct and mine was not: **a PostHog project key and a Sentry DSN are public by
design, so they belong in build-time `VITE_*` vars — a Cloudflare secret is a
runtime binding and can never reach a bundle Vite already inlined.** As written,
`wrangler.toml`'s `POSTHOG_KEY` / `SENTRY_DSN` secrets could never have worked,
which is a real bug I missed. It is genuinely wired (`analytics.ts:49` calls
`forwardEvent` from `trackEvent`), so no vacuous-test problem.

### The root cause, and it was mine

The bootstrap ran `git pull --rebase` first. It failed — "cannot pull with
rebase: You have unstaged changes" — and **that failure is not a no-op: git
refuses before it fetches, so I never learned the remote had moved.** I then read
`git rev-list --left-right --count origin/main...HEAD` as `0 8` off a stale ref
and built the item anyway. A separate `git fetch` would have shown `882ebcf`
immediately.

### Recovery

Reset my three commits away with `--mixed` (so the peer's 25 uncommitted route
files were never touched), restored my four superseded files to HEAD, deleted my
three new files, and inverted my two board edits. Then had to **restore
`a202fae`**, a colleague's board fix, because the resets moved HEAD one commit
further than expected twice in a row. Verified afterwards: my four files
byte-identical to HEAD, my three new files gone, `wrangler.toml` back on §8, the
peer's 29 dirty entries intact, the L10 row intact.

`git merge-tree --write-tree --name-only HEAD origin/main` puts the divergence at
**exactly one conflicted file** — `docs/14-LANES.md`; `docs/12` auto-merges — so
the rebase is a one-file job for whoever does it on a quiet tree. Not done here:
a peer was actively writing, and `--autostash` would have stashed their work.
