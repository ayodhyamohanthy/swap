## The two things nobody had checked: the gate, and what the domain serves

Both found by asking a question the lane board never asks: **does any of this
actually run?** Every lane had been verifying its own work in a browser and
against the test suite. Nobody had checked whether the pipeline that is supposed
to enforce all of it exists, or whether the URL the product is supposed to live
at serves the product.

They turn out to be the same story: **the only pipeline that reaches a live URL
is the one with no gate, and the gated pipeline has never executed.**

### 2. The product domain serves the prototype, not the app

`docs/12` §1 says the PWA shell is `app/dist/client/` on Cloudflare Workers

So the domain serves the **repo-root prototype** and the real TanStack app lives
only on a `workers.dev` subdomain.

- `gh api repos/.../pages` → `status: built`, `cname: toyoufromme.website`,
  `source: main / (root)`, `build_type: legacy`, `public: true`,
  `https_enforced: true`, cert approved, expiring 2026-12-21. **GitHub Pages
  owns the domain**, and `pages-build-deployment` rebuilds it on every push.
- `app/wrangler.toml` lines 21–22 keep the custom-domain route **commented out**
  — that is why Workers is on `workers.dev` and not on the domain.

The domain itself is not a surprise: `docs/12` line 9 names it, `CNAME` is
tracked (commit `f3a98bd`), and `app/tests/qa-placeholders.test.ts` even guards
against the domain leaking into copy. What was never checked is *which build
answers on it*.

Two consequences worth more than the mismatch:

1. **The only pipeline reaching a live URL has no gate.** Pages publishes
   `main`'s root whether or not typecheck, tests and build pass, and it
   *succeeds* on the very pushes where `green` fails. A red tree ships to the
   product domain. This is the thing that makes finding 1 more than a
   curiosity — the two together mean the repo's entire verification story is
   local-only, and its only automatic publisher is unverified.
2. **The root prototype is a second implementation of the money rules.** It has
   its own `seatswap-pay.js` and `seatswap-store.js` that nothing in
   `app/tests/` covers, plus its own `manifest.webmanifest` and `sw.js`. An
   installed PWA on the product domain is served by a service worker the
   TanStack build does not control — the stale-precache trap L3 already paid for
   once (`pwa-tour.mjs` reading a stale precache and printing `1 choice` after a
   correct deploy).

Filed as a request line to L1. Not fixed by me: `app/wrangler.toml` is L1's and
the root files are in no lane's map. Which way to resolve it — point the domain
at Workers, publish Pages from a branch, disable Pages, or delete the root
prototype — is a deploy decision.

### 4. The rules file does not exist under its own name

`AGENTS.md` is committed as **`agents.md`** — lowercase. `git ls-files` →
`agents.md`, added in `cad4911`, and the next commit touching it (`cccef08`)
already spells it `AGENTS.md` in its subject. All 11 prose references across
docs/10, 12, 13 and 14 use `AGENTS.md`.

macOS is case-insensitive, so on this machine both spellings resolve to the same
inode and **nothing here can see the problem**. Linux cannot — and `green.yml`
runs on `ubuntu-latest`. Confirmed against the live domain: `/AGENTS.md` → 404,
`/agents.md` → 200.

This one cost me a wrong conclusion before it became a finding. I curled
`/AGENTS.md`, got a 404, and briefly read it as "the rules file is untracked"
(`git ls-files --error-unmatch AGENTS.md` also fails, because git's pathspec is
case-sensitive too — two case-sensitive tools agreeing on the wrong answer).
The resolution was `git ls-files | grep -i agents`. **When a lookup fails, ask
whether the lookup is case-sensitive before concluding the thing is missing.**

Fix is a `git mv`, but **not a plain one** — on a case-insensitive filesystem a
direct rename silently does nothing. It needs
`git mv agents.md agents.md.tmp && git mv agents.md.tmp AGENTS.md`.

No script reads the file by path today, so nothing is broken yet. The cost is
that the one document every agent is told to read first does not exist under the
name it is given.

## L7 pass 10 — design 17's Swaps table, and a blocker I invented

Built the half of design 17 that was buildable: six columns (Swap / Train /
Requester / Acceptor / Status / Amount), a phase filter, one DOM at two widths.
Three things are worth keeping.

### I claimed a blocker that did not exist

Last pass I wrote that design 17's **Requester *and* Acceptor** columns were both
blocked on missing peer rows. The Acceptor half was wrong.

`SwapOffer.acceptor_name` exists and is documented as *"First name + initial —
the only identity ever shown (rule 13)"* — which is exactly the design's
`Arjun S`. And `useRequestsState()` already returns `offers` beside `requests`,
so the screen needed a **join, not a schema change**. Same reasoning gives
Amount: `PaymentRow` has `amount_paise` and `credit_used_paise`, so money
collected is `amount − credit_used`.

The mistake was reading `AdminSwapRow` — which carries neither field — and
concluding the data was absent. It lives in the two tables the screen was not
joining. **Only the Requester name is genuinely missing**, and `SwapRequest` has
no name field at all (`IncomingRequest.requester_name` exists for the inbound
path, so it is a `profiles` join, not a new idea).

The transferable rule, and it is the same one as "suspect the fixture before the
feature": **a missing field in the row type is not a missing field in the
model.** Before declaring something unbuildable, grep the schema for the noun —
`acceptor_name` was one grep away, and I had already written the claim into the
board where another lane would read it.

### The design's filter cannot reach four of nine states

Design 17 draws five chips — Waiting / Accepted / Paid / Done / To credit.
`RequestStatus` has **nine** values. Five chips therefore cannot reach four of
them, and one of the four is `disputed` — the only state where money is held and
a person has to decide. **A filter that cannot reach a state is a filter that
hides rows**, so the chip row is seven phases plus All: a deliberate deviation
from the design, filed on the board rather than quietly widened.

Two things fell out of doing it properly:

- `swapPhase()` is a `Record<RequestStatus, SwapPhase>`, so adding a status to
  the state machine is a **compile error** at the map, naming the missing key.
  Verified by deleting `disputed` and reading the error. That is a stronger
  guard than any runtime test, and it cost nothing.
- The screen had been rendering `row.status` **raw** — `locked`, `disputed`, an
  untranslated enum — which is the same defect class L7 filed against L10 for
  `actor_role`. `request.statuses.*` already existed in **both** languages with
  all nine values, so the fix was a lookup, not new copy. The pill now shows the
  phase and the tooltip the exact state, so the two vocabularies stay distinct.

Also worth keeping: design 17's Amount column prints **₹49** on a swap part-paid
with credit and **₹0** while nothing is paid, which independently confirms the
definition `moneyInTodayPaise` already used. A mockup agreeing with a metric is
cheap evidence and easy to miss.

Three guards mutation-checked: the `Record` (delete a key → compile error), the
locked-offer precedence (`locked_offer_id` must beat another still-accepted
offer → named the wrong acceptor), and the bilingual chip labels (rename one
Hindi key → `hi:admin.phaseToCredit`).

### A mutation test in a shared tree is a public act

This one is a process lesson and it nearly shipped a bug.

Mutation-checking the chip labels, I renamed a key in `app/locales/hi.json` to
`phaseToCreditMUTATED`. **Before I restored it, another agent ran `git add` and
staged the mutated file.** The index then held a Hindi catalogue with a broken
key, and any agent committing in that window would have shipped it — and my own
new guard would have failed on *their* commit, pointing at a file they never
touched.

I caught it by accident, comparing `git diff` against `git diff --cached`, and
fixed it by re-staging the restored file. The rule from here: **in a shared
working tree, mutate a file and restore it in the same breath, then immediately
re-stage it so the index can never hold the broken version.** Or mutate a copy
outside the repo. A mutation test assumes you are the only writer; here you are
never the only writer.

The wider fact this exposed: my in-flight `lib/admin.ts`, `admin.swaps.tsx` and
`admin.test.ts` had already been staged by someone else's blanket add, and
`app/locales/{en,hi}.json` had been **committed** by another lane's commit
mid-pass. Working here means your uncommitted work is other people's index
contents.

### The bug

`app/src/routes/admin.payments.tsx` line 24:

A literal empty array. The screen imported `createFileRoute`, `Button`,
`Card`, `Pill`, the CSV helpers, `useI18n` and two money constants — **and no

The comment was wrong twice: `usePayments()` already existed in
`lib/use-store.ts`, and `startPayment` writes a `PaymentRow` plus a
`payment_created` log line the moment checkout opens. The list was empty because
of the code, not the state.

**Why nothing caught it:** an empty table passes every text assertion. There is
no test that fails when a list is *always* empty unless you seed rows and count
them — which is now what the browser probe does.

Its two "tiles" were `FEE_PAISE` (₹49) and `THANK_YOU_PAISE` (₹50) — unit

### The tile the board said needed a definition did not need one

Backlog 4 recorded "Moved to credit" (₹297) as "genuinely new and needs a
definition … a money call rather than a layout one", because rule 6's ₹99
fallback and the acceptor's ₹50 thank-you are both `credit_added` rows.

They are. But `WalletTx.kind` already separates them:
`CREDIT_AMOUNTS = { acceptor_credit: 5000, swap_to_credit: 9900 }`.

What could not tell them apart was **`CreditLedgerRow`** — the narrow
`{id, amount_paise, expires_at}` view of the wallet the console reads through.
So the fix is a narrower filter, not a decision:

```ts
function creditIssuedPaise(rows: ActivityRow[], kind?: WalletTx['kind']): number
```

One function, one predicate, so `moved ⊆ given` holds **by construction**. Two
independent sums is exactly how that would stop holding.

Same shape as pass 10's mistake, mirrored: there, I read `AdminSwapRow` and
concluded the data was absent; here, the board read `CreditLedgerRow` and
concluded the definition was absent. **A missing field in the narrow view is not
a missing field in the model** — twice now.

Also corrected: the backlog claimed three of the four tiles were numbers the
lane "already computes", `creditUsedTodayPaise` among them. That one did not
exist.

### The probe passed while the table was visibly broken

The single most useful thing that happened in this pass, and it happened *after*
I had written "verified, zero overlaps" in a commit message.

The screenshot showed `Tue, 29 Sept · 22:41₹99` — the When text spilling out of
its track and printing hard against the amount. The When track was `6rem`
(96px); the string needs ~120px.

**Why every check was green:** they all compared **left edges**. The cell starts
in the right column; it merely runs past the *end* of it. Left edges are where a
cell begins. Overflow is where it ends.

**So I added a right-edge-vs-next-left check — and it passed too.** The reason is
the same `lg:contents` trick that makes this table work: at `lg` each cell is a
*grid item whose box fills its track*. The box never crosses the boundary. Only
the **text** does. Two rounds of "fix the check" and both measured the box.

**What actually works:**

```js
const spill = (el) => {
  const over = el ? el.scrollWidth - el.clientWidth : 0
  return over > 1 ? over : 0
}
```

`scrollWidth` is the content, `clientWidth` is the track. It works because a
grid item is blockified.

**And I proved the check can fail before trusting it** — the discipline applied
to the probe itself, not just to the unit tests:

| track | result |
|---|---|
| `6rem` (buggy) | `spillBy: 17 / 14 / 19`, naming the text |
| `8.5rem` (fixed) | `[]` |

A geometry assertion you have never seen fail is decoration.

**The fix was already in the repo.** Design 15's activity table uses `8.5rem`
for that identical `date · time` string — it had measured it already. I invented
a track width instead of grepping the sibling table's `grid-cols-[…]`. Two
tables in one console should not disagree about how wide a date is.

**The wider point.** The skill's own section on layout geometry says "a
screenshot is not optional … every automated check in the probe was green while
the table was visibly wrong; the screenshot is what found it." That happened
*again*, in the same repo, to someone who had read that sentence. The lesson is
not "remember the screenshot" — it is that **a geometry assertion encodes an
assumption about which measurement is fragile**, and mine was wrong twice. Take
the screenshot first, then let it tell you what to measure.

### Method note: `git commit -- <paths>` gives the hook a temporary index

Useful and non-obvious. `git commit -F msg -- <paths>` commits **only** those
paths from the working tree and leaves every other staged entry alone. The
pre-commit hook runs, and it reported `4 file(s) staged` — so git hands the hook
the *temporary* index, not the real one. That means a path-scoped commit cannot
sweep in a foreign staged file, which is precisely the trap that nearly shipped a
bug in pass 10. `.commandcode/settings.json` stayed staged and untouched.

### Method note: I nearly shipped a second copy of `activityTime`

I wrote a local `clockOf(iso, lang)` with an `Intl.DateTimeFormat` cache for the
payments When column — and `admin.ts` already exports `activityTime(iso, lang)`
doing exactly that, `localeFor` mapping and `hour12: false` included, because
design 15 needed it first. Caught by grepping before writing, not after. The
lesson is the lane's own theme pointed inward: **before adding a helper, grep for
the helper.** `shortId` was the same story in reverse — it was local to
`admin.swaps.tsx`, and moving it to `lib/admin.ts` is what stopped design 18's
table from getting a second copy.
