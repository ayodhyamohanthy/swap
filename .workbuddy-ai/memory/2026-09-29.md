# 2026-09-29

## The two things nobody had checked: the gate, and what the domain serves

Both found by asking a question the lane board never asks: **does any of this
actually run?** Every lane had been verifying its own work in a browser and
against the test suite. Nobody had checked whether the pipeline that is supposed
to enforce all of it exists, or whether the URL the product is supposed to live
at serves the product.

They turn out to be the same story: **the only pipeline that reaches a live URL
is the one with no gate, and the gated pipeline has never executed.**

### 1. `green.yml` has never run a single step

`docs/11` says `green.yml` is what makes "continue" safe. AGENTS.md §0 step 4
requires typecheck + test + build before every commit.

All **four** `green` runs that exist on `main` report `steps=0` and
`runner=""` — no runner was ever assigned — and each died 3–5 seconds after
creation. Latest: created `18:26:11Z`, job started `18:26:13Z`, failed
`18:26:16Z`. The check-run annotation, verbatim:

> "The job was not started because recent account payments have failed or your
> spending limit needs to be increased. Please check the 'Billing & plans'
> section in your settings"

Actions is **enabled** on the repo (`actions/permissions` → `enabled: true`,
`allowed_actions: all`), so this is an **account billing** block, not a repo
setting. It is not readable from here: the `gh` token's scopes are
`gist, read:org, repo, workflow` — **no `user`** — so
`users/<login>/settings/billing/actions` returns 404. Established facts: repo
`ayodhyamohanthy/swap` is **private**, owner type `User`, `disabled: false`,
`archived: false`.

This is a money-and-product call, so it belongs to Ayu, not to a lane. Filed as
a request line with three exits, cheapest first: clear the billing state (free,
and the message names exactly this), confirm the Student Pack's GitHub Pro is
actually applied to this account, or make the repo public for unlimited minutes.
If none is acceptable, **delete the workflow** — a red X on every push is worse
than no CI, because it trains agents to ignore red.

### 2. The product domain serves the prototype, not the app

`docs/12` §1 says the PWA shell is `app/dist/client/` on Cloudflare Workers
Static Assets at `toyoufromme.website`. Measured:

| URL | what it serves |
|---|---|
| `https://toyoufromme.website/` | `server: GitHub.com`; 13 vanilla scripts (`./js/seatswap-app.js`, `-auth`, `-config`, `-data`, `-demo`, `-engine`, `-i18n`, `-pay`, `-pnr`, `-screens1/2/3`, `-store`); **zero** `assets/index-*.js` |
| `https://seatswap.ayodhya-711.workers.dev/` | `assets/index-C2M2mw6V.js`; **zero** `seatswap-*.js` |

So the domain serves the **repo-root prototype** and the real TanStack app lives
only on a `workers.dev` subdomain.

- `gh api repos/.../pages` → `status: built`, `cname: toyoufromme.website`,
  `source: main / (root)`, `build_type: legacy`, `public: true`,
  `https_enforced: true`, cert approved, expiring 2026-12-21. **GitHub Pages
  owns the domain**, and `pages-build-deployment` rebuilds it on every push.
- `app/wrangler.toml` lines 21–22 keep the custom-domain route **commented out**
  — that is why Workers is on `workers.dev` and not on the domain.

The domain itself is not a surprise: `docs/12` line 9 names it, `CNAME` is
tracked (commit `f3a98bd`), and `app/tests/qa-placeholders.test.ts` even guards
against the domain leaking into copy. What was never checked is *which build
answers on it*.

Two consequences worth more than the mismatch:

1. **The only pipeline reaching a live URL has no gate.** Pages publishes
   `main`'s root whether or not typecheck, tests and build pass, and it
   *succeeds* on the very pushes where `green` fails. A red tree ships to the
   product domain. This is the thing that makes finding 1 more than a
   curiosity — the two together mean the repo's entire verification story is
   local-only, and its only automatic publisher is unverified.
2. **The root prototype is a second implementation of the money rules.** It has
   its own `seatswap-pay.js` and `seatswap-store.js` that nothing in
   `app/tests/` covers, plus its own `manifest.webmanifest` and `sw.js`. An
   installed PWA on the product domain is served by a service worker the
   TanStack build does not control — the stale-precache trap L3 already paid for
   once (`pwa-tour.mjs` reading a stale precache and printing `1 choice` after a
   correct deploy).

Filed as a request line to L1. Not fixed by me: `app/wrangler.toml` is L1's and
the root files are in no lane's map. Which way to resolve it — point the domain
at Workers, publish Pages from a branch, disable Pages, or delete the root
prototype — is a deploy decision.

### Method note

Both findings came from the same move: **check the claim, not the code.** Every
lane had read `docs/12` and believed it. Nobody had curled the domain it names,
and nobody had opened the workflow that the protocol leans on. A doc that
describes intent is not evidence that the intent is deployed — and in this repo
the gap between the two was a whole different application.

### A smaller one, about the board itself

The board's `active: <ISO time>` does not say local or UTC, and the two are now
mixed. L9's row reads `active: 2026-09-29T00:10Z` — local IST with a `Z` on it;
the true UTC instant was `2026-09-28T18:10Z` (the two files it describes were
written at local 00:14 and 00:16). The other lanes' claims are UTC. That is 5.5
hours of ambiguity in the one field a lane reads to decide whether a file is
another agent's. Filed as a docs/13 nit: claims are UTC.

Two rules that earned their keep here:

- **A board commit carries the claim lines that landed while you worked.** The
  L9 row change was already staged by another agent; committing
  `docs/14-LANES.md` carries it. Say so in the commit message rather than
  letting it look like mine.
- **Verify the heading survived.** The last time I appended to this file I
  anchored on `## Backlog (unclaimed, ready to pull)` and dropped it from the
  replacement, silently merging 200 lines of backlog into Requests. This time
  the edit was checked with `grep -n '^#'` immediately after — 3 headings, and
  the diff is 72 insertions, 0 deletions.
